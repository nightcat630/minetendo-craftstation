# 服务端 ROM 分发说明（给服主）

这个模组在**专用服务端**上只做一件事：把服主放进 `server-roms/` 的游戏文件列出来，并按需分片发给客户端。
服务端不跑模拟器、不需要显卡、不需要原生库。

---

## 1. 目录与开关

服务端工作目录下：

```
<服务端根目录>/
└── minetendo/
    ├── sfc/server-roms/      ← 客户端选"服务器"来源时看到的 SFC 游戏
    ├── gba/server-roms/
    ├── nds/server-roms/
    ├── nds3/server-roms/
    ├── ps2/server-roms/
    └── psp/server-roms/
```

- 目录不存在时会在首次启动自动建好，**放进去的文件立刻可见**（客户端点"刷新"即可，不用重启服务端）
- 只认这些后缀：`.sfc .smc .gba .nds .app .3ds .cci .cia .iso .chd .bin .cue .pbp .cso .elf .zip`（按机种不同）
- 单个文件上限 **4096 MB**，超过会被拒绝并记日志
- 文件名会被清洗：只允许字母/数字/中文/`._-()` 等安全字符，路径分隔符与 `..` 一律拒绝，防止目录穿越

对应代码：`src/main/java/com/november/minetendo/net/RomServerNet.java`

---

## 2. 客户端怎么拿到游戏

```
客户端点"来源: 服务器"
   → 发 RomListRequest（哪台机器）
服务端 RomServerNet
   → 扫 server-roms/ 回 RomListResponse（文件名 + 大小）
客户端选中 → RomDownloadRequest
服务端按 24KB 切片回 RomChunk（带序号）
客户端拼完 → 写进 <客户端>/minetendo/<机种>/roms/<文件名>.part → 改名
```

要点：

- **游戏文件只落在客户端本机**，服务端不参与运行
- 下载是**按需**的：不点就不传，避免开服就把带宽打满
- 同名文件已存在时客户端会跳过下载（列表里显示"已有"）
- 服务端只发文件内容，不做版本校验；客户端下完直接用，损坏请重下

---

## 3. 带宽与并发

- 每个分片 24KB，由 NeoForge 自定义包（`minetendo:rom_chunk`）承载，走 MC 自己的连接
- 一个 700MB 的 PS2 镜像 ≈ 3 万个分片。**这是走玩家连接的真实流量**，不是外链下载
- 建议：
  - 只放**小体积**经典游戏（SFC/GBA 几 MB 级），大镜像让玩家自己放本机
  - 高峰期别开大文件下载，玩家会感觉"卡"（那是他自己的连接被占满）
  - 需要分发给很多人时，更合适的做法是自己在服主群/网盘发文件，玩家丢进本机 `roms/`

---

## 4. ROM 分发与责任（重要）

- 模组**不内置任何游戏 ROM**，只提供"把服主自己放进去的文件发给连进来的客户端"这个管道
- `server-roms/` 里放什么、发给谁，**由服主自己负责**。请只分发你有权分发的文件：自制同人、公有领域、自己 dump 的卡带、明确授权的开源游戏
- 不要把商业游戏镜像放在公开服上给不特定玩家下载
- 同理，`bios/` 下的 PS2 BIOS 也只用于你自己的合法备份

这三条属于运维层面的自律，模组不会做内容审查，也没有办法替你判断某个文件的授权状态。

---

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 客户端"来源: 服务器"是空的 | `server-roms/` 目录放错层级（要在 `minetendo/<机种>/` 下），或文件后缀不在白名单 |
| 列表有文件但下载卡住 | 玩家连接被占满 / 文件超过 4096MB / 服务端磁盘读慢；看服务端日志有没有 `rom` 相关报错 |
| 下载完客户端仍显示未下载 | 客户端 `roms/` 只读，或磁盘满（`.part` 改名失败会在客户端日志里留痕） |
| 服务端日志刷 `RomServerNet` 警告 | 文件名含被清洗的字符，重命名成中文/英数即可 |
| 想让某些人看不到 ROM | 现在没有按权限过滤，靠"别放进去"来控制（后续可加白名单） |

## 6. 服务端不需要的东西

- ❌ 不需要图形环境、不需要显卡、不需要装原生库
- ❌ 不需要和客户端同版本的 ROM
- ✅ 只需要 NeoForge 21.1.200+、Java 21，以及上面那几个目录
